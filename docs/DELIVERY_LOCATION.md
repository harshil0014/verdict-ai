# Smart Delivery Location Verification

Submitting evidence automatically compares intended and reported delivery destinations before the existing Gemini investigation. The same source-backed panel appears in Investigation and Evidence, with exact passages, source links, original wording, explicit versus inferred PIN codes, provenance hashes, map precision and retained provider limitations. It is a comparison aid, not proof of fulfillment, physical delivery or personal receipt.

## Privacy and authorization

External lookup defaults **off** for every case, including existing accounts. Local source/PIN comparison still runs. In the panel's **Location privacy** settings, an authorized user can grant ongoing per-case permission for PIN-area lookup or extracted-address lookup. Evidence arriving afterward is processed automatically; there is no separate Verify GPS operation. Disabling permission stops future queries; it does not delete preserved evidence or earlier authorized results. In-flight requests cannot be recalled.

Area mode sends only a source-supplied six-digit Indian PIN plus country context, never the document or residential address. Address mode sends the extracted address after omitting unit/floor details; arbitrary names embedded in an address cannot be reliably redacted, so users must have authority to share it. The disclosure names Photon/OpenStreetMap and explains that displaying tiles shares the browser IP and visible geographic area. Maps do not load when permission is off. Existing evidence already follows the separate Gemini investigation consent. Raw geocoder responses, coordinates, comparisons and cache are private case data, protected by the existing session ownership, forced RLS, original/audit transaction and quotas; there is no shared public address cache.

## Provider choice and service boundaries

Current primary documentation was researched on 8 November 2026 (IST):

- [Photon](https://github.com/komoot/photon) is Apache-2.0 software with a public no-key demo API accepting reasonable low-volume projects; it offers no availability guarantee and may throttle/ban extensive usage. Its [documented GeoJSON API](https://github.com/komoot/photon/blob/master/docs/api-v1.md) supplies actual OSM objects and coordinates. It needs no account, card or billing. The app uses a distinct identifying User-Agent, a global PostgreSQL pacing slot of at least 1.25 seconds, at most 120 uncached queries/day across services and 20/account/day, and at most four fresh queries per evidence revision. A server-only switch `VERDICT_GEOCODING_ENABLED=false` disables external lookup without a frontend release.
- [Geoapify](https://apidocs.geoapify.com/docs/geocoding/forward-geocoding/) documents a no-card free API key and [3,000 daily credits](https://www.geoapify.com/pricing/). It remains an alternative requiring an account/key; this release does not open an account, activate billing or silently use a paid API.
- [Public Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/) restricts app-wide traffic, periodic/bulk lookup and confidential data. VERDICT deliberately **does not call public Nominatim**, including as a residential-address fallback.
- [Leaflet 1.9.4](https://leafletjs.com/) supplies an actual interactive map. [OSM tiles](https://operations.osmfoundation.org/policies/tiles/) use the documented HTTPS endpoint, visible ODbL attribution, normal browser caching, no prefetch/offline downloads, and an explicit origin-only tile referrer. Other requests retain the app's no-referrer policy. CSP permits only the specific tile image host. Unavailable tiles do not remove preserved location records.

Successful geocoding is cached privately for 30 days; failures for one hour. Failed lookup never causes invented coordinates. Previously preserved coordinates and text comparison remain available. There is no paid fallback or claim of guaranteed uptime. Stored response bytes and SHA-256 bind the result actually received; quote/source hashes bind each address to its original passage. OSM data/service attribution is separate from the project's MIT license; Leaflet's BSD-2-Clause and type-package MIT notices are retained.

## Interpretation

The extractor first recognizes source labels locally and, when needed, asks the existing Gemini API for bounded structured address mentions. Every accepted address and shipment reference must occur verbatim in its preserved quote/source. Models never supply map coordinates. Multiple unrelated addresses remain unverified unless a unique intended/reported pair or source-anchored shipment reference is established. Identical corroborating address mentions retain every original source while avoiding duplicate comparison pairs.

**LIKELY MATCH** requires compatible property wording, sufficiently precise supported map results and no unresolved material conflict. **POSSIBLE MATCH** includes compatible but approximate locations. **LOCATION MISMATCH** includes explicit conflicting PINs/units or widely incompatible mapped destinations. **UNVERIFIED** covers missing/ambiguous sources or insufficient usable mapping. A missing PIN is not a mismatch. Nearby coarse points do not prove the same building. Provider PINs are labeled inferred; source-supplied GPS is explicitly reported/unverified, and missing GPS accuracy stays missing.

Comparison tolerances vary by result class (building, site, street, postcode area, locality), are enlarged for provider extents, and are labeled conservative application policy rather than guaranteed provider accuracy. A campus is not promoted to a precise building. Postcode queries select a compatible postcode object, not a convenient POI returned first. Multiple plausible objects remain ambiguous instead of selecting an invented exact location. Distances use the haversine formula and describe map estimates, not parcel routes.

The derived record is stored and audited before reassessment. The existing investigation receives comparisons, limitations and original source references, excluding raw provider JSON. Source text remains unchanged. No map result changes a PayPal status or executes a dispute action. A fourth-generation worker requirement prevents older retained workers consuming newly location-enabled jobs. The additive migration adds server-only quota RPC/compatibility logic without changing account ownership or deleting data.

## Verification

Deterministic tests cover missing PINs, explicit nearby PIN contradictions, distinct nearby buildings, precise and widely separated locations, vague details, campuses, ambiguous results, invalid/nonfinite coordinates, source anchoring, document instructions, undocumented GPS precision, HTTP 403/429/503, privacy defaults, cache reuse, authorization revocation and cross-account routes. These fixtures/mock transports are not claimed as actual provider responses. Real public-address and deployed acceptance records are published only after execution. The frozen 28/30 engine evaluation is unchanged.
